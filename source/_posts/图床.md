# GitHub + PicGo 搭建免费图床

> 用 GitHub 仓库当图床，配合 PicGo 一键上传，完全免费、稳定可靠。本教程从零开始，手把手教你搭一套属于自己的图床系统。

---

## 为什么需要图床

写博客、写笔记、写文档，都离不开图片。把图片直接存在本地会导致：

- 换电脑后图片丢失
- 文章迁移困难
- Markdown 文件体积越来越大

**图床**就是把图片统一上传到一个稳定的服务器上，文章里用外链引用。好处是：

- 文章只存链接，文件轻量
- 图片集中管理，方便查找替换
- 任何设备、任何平台都能访问

## 一、创建 GitHub 仓库

### 1.1 注册 GitHub

前往 [github.com](https://github.com/) 注册账号。已有账号的直接登录。

### 1.2 新建仓库

1. 点击右上角 `+` → **New repository**
2. 仓库名称随意命名，比如 `my-image-host` 或 `blog-images`
3. **必须设置为 Public**（公开仓库），否则图片外链无法访问
4. 勾选 **Add a README file**（可选，建议勾选）
5. 点击 **Create repository**

### 1.3 获取 Token

GitHub 不允许直接推送文件到仓库，需要创建一个 Personal Access Token 作为"钥匙"。

1. 点击头像 → **Settings**（设置）
2. 左下角 → **Developer settings**
3. 选择 **Tokens (classic)**
4. 点击 **Generate new token (classic)**
5. 填写配置：
   - **Note**：随便写，比如 `picgo`
   - **Expiration**：选择 **No expiration**（永不过期）
   - **Scopes**：勾选 **repo**（必须有这个权限）
6. 点击 **Generate token**
7. **立即复制保存** `ghp_xxxxxxxxxxxx` 开头的 token，页面刷新后无法再次查看

> ⚠️ Token 相当于密码，不要泄露给别人，也不要提交到代码仓库。

## 二、安装配置 PicGo

### 2.1 下载安装

前往 [PicGo Releases](https://github.com/Molunerfinn/PicGo/releases) 下载最新版本。

- Windows 选 `PicGo-Setup-x.x.x.exe`
- macOS 选 `PicGo-x.x.x.dmg`

安装过程一路 Next 即可。

### 2.2 界面汉化

打开 PicGo，默认是英文界面：

1. 点击左上角 **Plugins Settings**（插件设置）
2. 找到 **Choose Language** 插件
3. 选择 **简体中文**，重启 PicGo

### 2.3 配置 GitHub 图床

1. 点击左侧 **图床设置**
2. 找到 **GitHub**，点击 `+` 新建配置
3. 填写以下信息：

| 配置项 | 填写内容 | 说明 |
|--------|----------|------|
| 图床配置名 | 自定义，比如 `我的图床` | 方便识别的名字 |
| 设定仓库名 | `你的用户名/仓库名` | 格式必须是 `用户名/仓库名` |
| 设定分支名 | `main` | 大多数仓库用 main 分支 |
| 设定 Token | 上一步获取的 token | 粘贴 `ghp_` 开头的字符串 |
| 设定存储路径 | 留空 或 `images/` | 留空=根目录，填 `images/`=自动创建文件夹 |
| 自定义域名 | 留空 | 后面讲 CDN 加速时再填 |

4. 点击 **确定** 保存

### 2.4 测试上传

1. 切换回 **上传区**
2. 拖入一张图片或点击选择文件
3. 格式选择 **Markdown**
4. 点击 **上传**
5. 如果成功，会生成类似 `![image](https://cdn.jsdelivr.net/gh/用户名/仓库名@main/images/xxx.png)` 的链接

复制这个链接，粘贴到博客文章里就能显示图片了。

## 三、配置 jsDelivr CDN 加速

GitHub 原生的图片访问速度在国内不太理想，建议配置 jsDelivr CDN 做加速。

### 3.1 修改 PicGo 自定义域名

在 PicGo 的 GitHub 图床配置中：

- **自定义域名** 填入：`https://cdn.jsdelivr.net/gh/你的用户名/仓库名@main`

上传后生成的链接格式会自动变成：
```
https://cdn.jsdelivr.net/gh/用户名/仓库名@main/images/xxx.png
```

### 3.2 jsDelivr 的优势

- 全球 CDN 节点，访问速度快
- 自动 HTTPS
- 支持缓存优化
- 完全免费

## 四、使用规范与建议

### 4.1 文件命名

给图片起个好名字，方便日后查找：

| 不好 | 好 |
|------|-----|
| `screenshot.png` | `leetcode-198-houserobber.png` |
| `IMG_20240101.jpg` | `bg-anime-miku-4k.jpg` |
| `image.png` | `docker-compose-example.png` |

**建议命名规则**：`文章名-功能说明.扩展名`

### 4.2 目录结构

在 GitHub 仓库中按分类存放图片：

```
仓库根目录/
├── images/
│   ├── posts/          # 文章配图
│   ├── gallery/        # 图库
│   ├── avatar/         # 头像
│   └── bg/             # 背景图
```

在 PicGo 的 **存储路径** 中填入 `images/posts/`，上传时自动归类。

### 4.3 图片压缩

上传前先压缩，减小文件体积：

- **TinyPNG**（https://tinypng.com）— 在线压缩，效果优秀
- **Squoosh**（https://squoosh.app）— 谷歌出品，支持格式转换
- **PicGo 插件**：安装 `picgo-plugin-compress` 自动压缩

### 4.4 容量管理

GitHub 公开仓库单文件限制 100MB，仓库总容量建议控制在 1GB 以内（太大可能触发限制）。定期清理不需要的图片。

## 五、常见问题

**Q: 上传后图片显示 404？**

A: 检查以下几点：
1. 仓库是否为 Public（公开）
2. Token 是否有 `repo` 权限
3. 自定义域名格式是否正确
4. 图片路径是否拼写正确

**Q: 上传速度很慢？**

A: 国内访问 GitHub 较慢，建议：
1. 开启代理/VPN
2. 使用 jsDelivr CDN 加速访问（已经配置的话）
3. 批量上传时降低并发数（PicGo 设置 → 上传设置 → 重试次数）

**Q: Token 过期了怎么办？**

A: 回到 GitHub Developer settings，删除旧 token，重新生成一个，然后在 PicGo 中更新配置。

**Q: 可以绑定自己的域名吗？**

A: 可以，但不推荐。jsDelivr 已经足够快，绑定自定义域名需要购买域名 + 配置 DNS + 配置 CDN，成本较高。

**Q: 图片太多 GitHub 仓库爆了怎么办？**

A: 定期清理旧图片，或者迁移到付费方案（阿里云 OSS、腾讯云 COS），这些服务更稳定且容量更大。
